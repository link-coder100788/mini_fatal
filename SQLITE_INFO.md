# SQLite usage info

This document explains the optional SQLite support in `mini_fatal.h`.

`mini_fatal` is a single-header library. By default, the SQLite-related pieces are not enabled. SQLite support is controlled by the feature macro:
```c
#define MF_ENABLE_SQLITE
```
When `MF_ENABLE_SQLITE` is defined before including `mini_fatal.h`, the header exposes helper functionality for storing fatal-error information in a SQLite database.

## What the SQLite feature does

The SQLite support is intended to let applications record fatal-error diagnostics into a database table.

When enabled, the library provides helpers for:

- creating the expected SQLite table;
- storing fatal-error information in that table;
- recording useful debugging fields such as:
  - user message;
  - source file;
  - source line;
  - function name;
  - timestamp generated by SQLite.

The table used by the library is named:
```sql
mf_errors
```
The stored fields are intended to make it easier to inspect failures after a program run, especially when stderr output is not enough or when errors need to be collected over time.

## SQL copies used by tests

A copy of the SQL used for SQLite testing is kept in:
```text
test/sql
```
That directory contains standalone `.sql` files used by the test suite. These files are useful as references if you want to see the schema or test SQL outside of the header implementation.

For example, the test SQL directory may include files such as:
```text
test/sql/create_table.sql
test/sql/insert_error.sql
```
These files are not required at runtime by the header. They are copies/reference SQL for tests and documentation purposes.

## Enabling SQLite support

To enable SQLite features, define `MF_ENABLE_SQLITE` before including `mini_fatal.h`.

If you are also using the single-header implementation pattern, define `MINI_FATAL_IMPLEMENTATION` in exactly one translation unit.

Example:
```c
#define MINI_FATAL_IMPLEMENTATION
#define MF_ENABLE_SQLITE
#include "mini_fatal.h"
```
Or, in a separate translation unit where the implementation is emitted:
```c
#define MINI_FATAL_IMPLEMENTATION
#define MF_ENABLE_SQLITE
#include "mini_fatal.h"
```
Other files can include the header normally, but they should use the same feature macro configuration when they need the SQLite declarations:
```c
#define MF_ENABLE_SQLITE
#include "mini_fatal.h"
```
## User responsibility: SQLite headers and linking

When compiling with `MF_ENABLE_SQLITE` defined, SQLite becomes an external dependency.

It is the user's responsibility to:

1. make the SQLite development header available;
2. include/use `sqlite3.h` through the enabled header path;
3. create and manage their own `sqlite3*` database handle;
4. link the final program against the SQLite library.

On many Unix-like systems, the linker flag is:
```sh
-lsqlite3
```
A typical compile command might look like:
```sh
cc -DMINI_FATAL_IMPLEMENTATION -DMF_ENABLE_SQLITE main.c -lsqlite3 -I/path/to/sqlite3/include
```
Or for C++:
```sh
c++ -std=c++20 -DMINI_FATAL_IMPLEMENTATION -DMF_ENABLE_SQLITE main.cpp -lsqlite3
```
The exact package name and install command depends on your platform. For example, you may need to install the SQLite development package before compilation so that `sqlite3.h` and the SQLite library are available.

## The library does not create your database handle

`mini_fatal` does not open the database for you.

You must create your own SQLite database connection and pass the resulting `sqlite3*` to the SQLite-enabled helpers.

A minimal example looks like this:
```c
#define MINI_FATAL_IMPLEMENTATION
#define MF_ENABLE_SQLITE
#include "mini_fatal.h"

int main(void) {
sqlite3* db = NULL;

    if (sqlite3_open("errors.db", &db) != SQLITE_OK) {
        mf_fatal("failed to open sqlite database");
    }

    mf_sqlite_create_table(db);

    mf_fatal_store(db, "something went wrong");

    sqlite3_close(db);
    return 0;
}
```
Important notes:

- `sqlite3* db` belongs to your application.
- Opening the database is your job.
- Closing the database is your job.
- Choosing the database path is your job.
- Linking with SQLite is your job.
- The header only provides optional helpers once SQLite support is enabled.

## Main SQLite functions/macros

When `MF_ENABLE_SQLITE` is defined, the SQLite support includes:
```c
void mf_sqlite_create_table(sqlite3* db);
```
Creates the `mf_errors` table if it does not already exist.
```c
#define mf_fatal_store(db, msg)
```
Stores a fatal-error record using the current source location information.

The stored record includes the message passed by the user, plus file, line, and function information captured at the call site.

## Summary

SQLite support in `mini_fatal` is optional and macro-gated.

Use it when you want fatal-error information written to a SQLite database. Define `MF_ENABLE_SQLITE`, provide SQLite development files, link with `-lsqlite3`, and manage your own `sqlite3*` database connection.

The SQL used by the tests is copied in `test/sql` for reference.
